# 01. 최신 앱 구조·UI 벤치마킹 리서치

- 작성일: 2026-10-15
- 작성: UX 리서처 (SharePresent 디자인팀)
- 목적: 최신 유행하는 모바일 앱의 화면 구조(IA)와 UI 패턴을 조사하고, SharePresent 개편 방향의 근거로 삼는다.

## 1. 벤치마킹 대상과 핵심 패턴

| 서비스 | 관찰한 구조 | 가져올 패턴 | SharePresent 적용처 |
|---|---|---|---|
| **토스 (Toss)** | 가입·송금 퍼널을 화면 하나에 질문 하나로 분리(One thing per page). "3초 안에 답할 수 있는 질문", 하단 고정 CTA | 단계형 퍼널, 하단 고정 CTA, 단계마다 결정 1~2개 | 선물 상자 생성 플로우 4단계 분리 |
| **카카오톡 선물하기** | 상황 칩(생일, 집들이 등) → 가격대 → 랭킹 순으로 좁히기. 받는 사람이 옵션과 주소를 직접 입력 | 상황(Occasion) 우선 진입, 가격대 칩, 수령인 옵션 자율 | 1단계에서 '상황 선택'과 예산을 함께 받음 |
| **29CM / 무신사** | 에디토리얼과 커머스의 하이브리드. 2열 상품 그리드, 브랜드명 대문자 타이포, 여백 중심 | 2열 컴팩트 그리드, 이미지 우선 카드, 선택 체크 오버레이 | 2단계 선물 고르기 그리드 |
| **iOS / Material 3 공통** | 하단 탭바(3~5개), Bottom Sheet, Progressive Disclosure | 하단 탭바 내비게이션, 바텀시트 확인창, '더 꾸미기' 접이식 | 앱 셸, 대시보드 취소 확인, 카드 고급 옵션 |
| **2026 트렌드: Bottom Sheet + Step Wizard + Sticky CTA** | 긴 폼은 쓰이지 않는 추세. 세그먼트 진행 바, 미완료 시 CTA 비활성화와 사유 표시 | 진행 바, 검증 상태를 반영하는 CTA | StepProgress, StickyActionBar |

### 1-1. 토스 Product Principles 요약
- **One thing per page**: 한 화면에서는 한 가지 질문이나 행동만 요구한다.
- **Easy to answer**: 모든 질문은 3초 안에 답할 수 있어야 한다. 선택지는 프리셋으로 줄인다.
- **Clear action**: 지금 할 일이 하단 CTA 하나로 명확해야 한다.
- **Value first, cost later**: 결제와 정보 입력 전에 가치(미리보기)를 먼저 보여준다.

### 1-2. 카카오톡 선물하기 요약
- 진입은 '누구에게, 어떤 상황'이 먼저이고 상품 탐색은 그다음이다.
- 상황 칩과 가격대 칩으로 결정 장애(Choice Overload)를 줄인다.
- 받는 사람이 옵션과 배송지를 직접 고르므로 보내는 사람의 부담이 적다. SharePresent의 핵심 가치와 같다.

### 1-3. 29CM 요약
- 브랜드명은 대문자에 넓은 자간, 상품명은 굵은 한글로 쓴다. 정보 밀도는 낮게, 이미지는 크게 둔다.
- 2열 그리드로 한 화면에 4~6개 상품을 비교할 수 있다. 1열 대형 카드는 2개 정도만 들어간다.

## 2. SharePresent 현황 감사 (2026-10-15, 430px 모바일 폭 실측)

| # | 문제 | 심각도 | 근거 |
|---|---|---|---|
| P1 | 생성 페이지가 약 **15화면 높이**의 단일 스크롤 폼이다. 결정 지점 11개 이상(프리셋, MD Pick, 이름, 메시지, 테마, 폰트, 포장, 씰, 예산, 직접 입력, PIN, 검색, 상품)이 한 화면에 몰려 있다 | 🔴 높음 | `app/page.tsx` 1,037줄 |

| P3 | 헤더 메뉴 4개가 모바일 폭에서 줄바꿈된다("Create / Gift") | 🟠 중간 | 스크린샷 |
| P4 | **수령인 화면에 보내는 사람용 내비와 Admin 링크가 노출**된다. 맥락이 혼란스럽고 운영 메뉴가 드러난다 | 🔴 높음 | `Header.tsx` 공용 사용 |
| P5 | 대시보드 취소 시 브라우저 `confirm()`을 쓴다. 디자인이 깨지고 사용자 흐름이 차단된다 | 🟠 중간 | `dashboard/page.tsx` |
| P6 | 상품 카드가 1열 4:3 대형이라 한 화면에 1.5개만 보여 비교가 어렵다 | 🟠 중간 | `ProductCard.tsx` |
| P7 | 9~10px 텍스트와 이모지가 과다하게 쓰였다. 럭셔리 톤과 접근성이 저하된다 | 🟡 낮음 | 전역 |
| P8 | 카드를 꾸며도 결과를 미리 볼 수 없다(Value first 원칙 위반) | 🟠 중간 | 생성 페이지 |

## 3. 시사점 → 개편 원칙 (디자인팀 회의 안건)
1. **단계 분리**: 상황·예산 → 선물 → 카드 → 확인·결제의 4단계로 나누고, 단계마다 핵심 결정은 1~2개로 제한한다.
2. **하단 고정 CTA**: 언제나 '다음' 행동이 엄지 영역에 있어야 한다. 미완료 시 사유를 표시한다.
3. **맥락별 셸**: 보내는 사람에게는 하단 탭바, 수령인에게는 로고만 있는 미니멀 헤더를 둔다(가격·운영 정보 완전 분리).
4. **2열 그리드**: 비교하기 쉽게 하고 선택 상태는 체크 오버레이로 표시한다.
5. **실시간 미리보기**: 카드 꾸미기 단계에서 결과 카드를 상단에 고정한다.
6. **Progressive disclosure**: 폰트·포장·씰·PIN은 '더 꾸미기' 아코디언에 둔다.
7. **브랜드 유지**: 세이지 그린(#3b483a)과 아이보리를 유지하고, 이모지는 줄이며, 본문은 최소 12px로 한다.
